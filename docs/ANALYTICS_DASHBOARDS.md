Analytics Dashboards
====================

Purpose
-------
- Provide minimum viable dashboards for monitoring analytics metric throughput, error rates, and latency using rollup artifacts generated by `scripts/metrics_rollup.js`.
- Establish a shared definition of the fields exposed in `var/analytics/rollup.jsonl` (or the downstream warehouse table) so operators and analysts can create consistent charts.

Data Sources
------------
- **Daily rollups (`rollup.jsonl`)** — Each line is a JSON object with:
  - `date` (ISO `YYYY-MM-DD`)
  - `metric` (metric name, e.g., `requests_total`, `errors_total`, `latency_ms`)
  - `count` (number of events ingested for that metric on the given date)
  - `numericCount` (subset of `count` where `value` parsed as a number)
  - `p95` (95th percentile across numeric values; `null` if insufficient numeric data)
  - `generatedAt` (ISO timestamp when the rollup was produced)
- **Raw sink (`metrics.jsonl`)** — Optional for drill-down. Each line mirrors the analytics metric contract (`name`, `value`, `labels`, `timestamp`).
- **Dead-letter queue (`broker.dlq`)** — Optional for error investigation. Surface as a secondary panel when DLQ metrics are published.

Dashboard Layout
----------------
1. **Arrival Rate (Area/Bar)**
   - Query: group `count` by `date` for `metric = 'requests_total'` (or other ingress counters).
   - Visual: stacked area or grouped bar to break down by `labels.service` or comparable dimension (if enriched during rollup/ETL).
   - Goal: spot volume trends and drops in ingest.

2. **Error Rate (Line with Dual Axis)**
   - Query: compute daily `errors_total` vs `requests_total`.
     - Error Rate = `errors_total.count / requests_total.count` (fallback to 0 when denominator missing).
   - Visual: dual-axis line chart where the primary axis tracks counts and the secondary axis shows the computed error percentage.
   - Alerting: flag days where error rate exceeds agreed threshold (e.g., >2%).
   - Notes: ensure both metrics are emitted; if not, derive from DLQ counts or a dedicated `error` metric.

3. **Latency (Histogram + Trend)**
   - Query: use `latency_ms` rollups.
   - Visuals:
     - Daily p95 trend (line chart of `p95` by `date`).
     - Optional histogram of raw values if rollups are exploded into warehouse tables.
   - Thresholds: compare against SLO targets (e.g., p95 < 300 ms). Configure conditional coloring for breaches.

4. **Top Labels / Dimensions (Table)**
   - Query: pivot latest 7 days of rollups by `metric` and label (requires label extraction pipeline or derived tables).
   - Visual: table listing `metric`, `label`, `count`, `p95`. Useful for spotting hotspots (e.g., specific services spiking latency).

5. **DLQ Intake (Bar)**
   - Query: count DLQ events with `originalTopic = 'analytics.metric'` per day.
   - Visual: bar chart to highlight ingestion failures. Use the same color palette as error rate for correlation.

Recommended Queries
-------------------
> Replace `<ROLLUP_TABLE>` with the path to your warehouse table or use `jq` against the JSONL file.

- **Arrival Rate**
  ```sql
  SELECT date, metric, count
  FROM <ROLLUP_TABLE>
  WHERE metric = 'requests_total'
  ORDER BY date DESC;
  ```

- **Error Rate**
  ```sql
  WITH daily AS (
    SELECT date,
           SUM(CASE WHEN metric = 'errors_total' THEN count ELSE 0 END) AS errors,
           SUM(CASE WHEN metric = 'requests_total' THEN count ELSE 0 END) AS requests
    FROM <ROLLUP_TABLE>
    WHERE metric IN ('errors_total', 'requests_total')
    GROUP BY date
  )
  SELECT date,
         requests,
         errors,
         CASE WHEN requests > 0 THEN errors::decimal / requests ELSE 0 END AS error_rate
  FROM daily
  ORDER BY date DESC;
  ```

- **Latency p95**
  ```sql
  SELECT date, p95
  FROM <ROLLUP_TABLE>
  WHERE metric = 'latency_ms'
  ORDER BY date DESC;
  ```

Ops Checklist
-------------
- Schedule `npm run metrics:rollup` (or equivalent job) shortly after midnight UTC to populate the rollup file/table before dashboards refresh.
- Ensure rollup output is ingested into the BI tool (JSONL -> warehouse load job or direct filesystem connector).
- Verify that new metrics added to the sink are reflected in dashboards by updating legends, filters, and queries.
- Monitor DLQ volume for sustained spikes; coordinate with service owners to remediate ingestion issues.
