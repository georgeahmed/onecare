Task: BE-01.13 — Audit ledger resiliency (async WORM, redaction)

Context
- Ensure audit writes are resilient, non-blocking, and redacted appropriately while targeting a WORM-compliant store.

Files
- packages/ports/src/audit.ts
- apps/orchestrator/src/index.ts
- schemas/audit/audit-event.json (existing)
 - var/spool/audit (runtime spool dir)

Steps
1) Introduce async, non-blocking audit writes with bounded queue and backoff on failure. On timeout/error, append JSONL to `var/spool/audit/YYYYMMDD/*.jsonl` using atomic write (tmp file + rename).
2) Enforce redaction policy before write (no PHI/PII/secrets); include `correlationId`, outcome tags, and minimal payload references. Validate against `schemas/audit/audit-event.json` before enqueue.
3) Add counters `audit.write.success`, `audit.write.timeout`, `audit.spool.size` and gauge for queue depth; expose timeouts and backoff via config.
4) Add background flusher to drain spool on recovery with exponential backoff; delete lines on success (or rotate file). Cap total spool size and surface warning metric.

Acceptance Criteria
- HTTP flow never blocks on audit writes; bounded queue prevents memory growth.
- Redaction verified; metrics present; typecheck passes.
 - Spool files created on failure and drained on recovery; caps enforced.

Validate
- Simulate audit sink failure; observe retries and bounded queue without impacting HTTP responses.
 - Verify spool files created and later removed after backend recovers.
