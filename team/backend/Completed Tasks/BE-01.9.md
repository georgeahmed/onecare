Task: BE-01.9 — Orchestrator state machine skeleton

Context
- Introduce an explicit state machine using @onecare/statekit with small, testable state classes, clear time budgets, and typed Decision/Result objects. Keep business logic in application states and I/O in adapters.

Files
- apps/orchestrator/src/application/states/*.ts (new)
- apps/orchestrator/src/index.ts (wire)
- packages/statekit (dependency already in stack)

Steps
1) Define states: IngressValidated -> SecurityChecked -> Normalized -> FhirValidated -> Persisted -> Published -> Completed | Diverted | Failed.
2) Each state: accepts typed context; returns a typed Decision/Result; no side effects inside pure transitions. Emit explicit `Intent[]` describing required adapter calls.
3) Enforce per-state and total time budgets (config-driven). Abort with a controlled failure Decision on budget breach and include `remainingBudgetMs` in logs.
4) Keep I/O in adapters invoked by states via ports (@onecare/ports); no business logic in adapters. Adapters execute `Intent[]` atomically per state where applicable.
5) Unit-test transitions: success path, deny path, and error path; ensure deterministic outcomes. Validate intents for each path.

Types
- `type Intent = { kind: 'PublishTriage' | 'Audit' | 'UpsertFhir'; payload: unknown }`.
- `interface OrchestratorCtx { correlationId: string; idempotencyKey?: string; budgetMs: number; startedAt: number }`.

Acceptance Criteria
- State graph covers success, deny, and failure paths with typed Decisions.
- Time budgets enforced; budget breach causes a controlled failure state.
- Unit tests pass for core transitions.

Validate
- npm run typecheck && npm run test
- Trace a sample request and confirm state transitions logged with correlationId.
