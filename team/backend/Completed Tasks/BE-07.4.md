Task: BE-07.4 — Outbound reliability (publish guardrails + DLQ)

Context
- Wrap bus publishes with timeout/retry and a circuit breaker; route failures to `broker.dlq` with sufficient context for reprocessing.

Files
- apps/ics-hub/src/application/ics.state.ts
- apps/ics-hub/src/adapters/bus.adapter.ts (new)
- packages/events/src/topics.ts

Steps
1) Add a bus adapter with `publishWithGuard(topic, payload, corrId)` applying timeouts, retries with jitter, and breaker per topic.
2) On persistent failure, publish a DLQ message to `broker.dlq` capturing `originalTopic`, `payloadRef` (or payload if small), and `correlationId`.
3) Ensure all publishes in ICS Hub go through this adapter.
4) Add unit tests using a fake bus that fails N times, asserting retries and DLQ fallback.

Acceptance Criteria
- Retries occur on transient failures; persistent failures result in DLQ publish with correlationId.
- Typecheck passes; unit tests deterministic.

Validate
- npm run test
