Task: BE-02.7 — Ordering & partitioning

Context
- Provide predictable ordering within a key (e.g., per patient or task) and partition load across consumers.

Files
- packages/events/src/topics.ts (naming guidance)
- packages/bus/src/natsBus.ts

Steps
1) Define a strategy: per-tenant and/or per-entity key routing via subject suffixes or message headers. Document constraints.
2) Ensure subscribe supports queue groups and that messages for the same key map to the same partition/consumer consistently.
3) Provide helper to compute partition key from payload/envelope.

Acceptance Criteria
- Messages for the same key are processed in-order by a single consumer; distribution across keys is balanced.

Validate
- Unit/integration test with sequences for a key and multiple keys; assert ordering and distribution.
