Task: BE-04.5 — Idempotent booking & dedupe (natural key; exactly-once publish)

Context
- Prevent double-booking by deriving a natural idempotency key for requests and ensuring exactly-once write-back and event publish.

Files
- apps/booking/src/index.ts
- packages/ports/src/idempotency.ts
- packages/events/src/topics.ts

Steps
1) Derive idempotency key from practiceId + patientId + slotId + window; accept `x-idempotency-key` override.
2) Use `IdempotencyStore.reserve(key, ttl)` before calling GP Connect; on exists → return 409 envelope without side-effects.
3) After successful create + write-back, mark reservation committed (if available) or rely on TTL expiry; include key in logs/metrics.
4) Publish `booking.appointmentCreated` exactly once with the key in envelope metadata.

Acceptance Criteria
- Second identical booking within TTL returns 409 and no double-book.
- Publish occurs once; consumers dedupe with the provided key.

Validate
- Sequential and concurrent duplicate requests tests; assert only one success and one event publish.
