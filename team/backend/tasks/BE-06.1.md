Task: BE-06.1 — Portal Uptime Guard schedule

Context
- Keep portal state aligned with configured core hours, safely across time zones and DST transitions (Algorithm.md 2.1). Avoid thundering herds, ensure idempotent state enforcement, and emit telemetry.

Files
- apps/access-gate/src/scheduler.ts
- apps/access-gate/src/application/portal.state.ts
- @onecare/config (core_hours, ooh_policy)
- packages/observability/src/logger.ts (reference)

Steps
1) Implement a tick scheduler running every 60s with ±5s jitter. Compute local time using practice time zone; fall back to a default if missing.
2) Add `ensurePortalState(now, cfg)` in application layer: pure decision function returning intents (e.g., SetBanner, OpenPortal, ClosePortal). Do not perform I/O here.
3) Add adapter to execute intents idempotently. Ensure repeated ticks cause no duplicate side effects (idempotency keys and current-state checks).
4) Guard for replicas: implement a lightweight in-process singleflight with a short TTL to reduce duplicate work; note that true leader election may be added by SRE later.
5) Emit metrics: `portal.tick`, `portal.state.changed`, `portal.state.unchanged`, and include `practiceId` and `correlationId` in logs.

Acceptance Criteria
- Scheduler is TZ/DST safe; no double toggles on DST change days.
- State enforcement is idempotent; repeated ticks without state change produce no side effects.
- Metrics/logs present and structured; no PHI in logs.

Validate
- Use fake timers to simulate across DST boundaries; assert correct decisions.
- npm run build && npm run typecheck && npm test
