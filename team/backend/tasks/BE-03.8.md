Task: BE-03.8 — SLA aging and escalation

Context
- Age open triage tasks and escalate priority or notify queues based on configured SLAs. Use deterministic timers; ensure graceful shutdown.

Files
- apps/triage/src/sla/aging.ts (new)
- apps/triage/src/index.ts (scheduler wiring)
- config/nhs_gp_defaults.yaml (triage.aging_interval, sla_targets)
- packages/ports/src/fhir.ts (update Task)
- packages/events/src/topics.ts (tasks.updated)

Steps
1) Implement a scheduler loop (e.g., setInterval with small jitter) running every `config.triage.aging_interval` to scan eligible items (abstracted via a repository port or in-memory index for demo).
2) For each item, compute elapsed against `sla_targets` and decide: escalate priority, notify owner, or mark breach. Avoid long blocking; cap per-iteration work and time.
3) Update FHIR Task via repo port; publish `tasks.updated` with minimal payload (taskId, patientId, newPriority, reason).
4) Respect time budgets; stop scheduler on SIGTERM and await in-flight operations with a bounded grace period.
5) Metrics: `sla.escalate`, `sla.breach`, `sla.scan.duration`.

Acceptance Criteria
- Escalations occur per configured targets; updates are idempotent (no repeated escalations).
- Clean shutdown without partially applied changes; metrics emitted.

Validate
- Unit tests for decision logic using fixtures across boundary times; simulated clock where needed.
