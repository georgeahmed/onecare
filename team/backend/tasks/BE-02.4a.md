Task: BE-02.4a — NATS connection + durable subs + ack deadlines

Context
- Implement a real NATS adapter for `@onecare/bus` with durable subscriptions and proper ack/deadline handling to support at-least-once delivery.

Files
- packages/bus/src/nats.ts (new)
- packages/bus/src/types.ts (reuse interfaces)
- apps/orchestrator/src/index.ts (inject adapter via factory later)

Steps
1) Implement `NatsBus` with `publish(topic, payload, headers?)` and `subscribe(topic, handler)` bridging to NATS subjects. Serialize payloads as JSON; set `correlationId` header when present.
2) Use JetStream (preferred) or core with manual ack; configure durable consumer with ack wait and redelivery policy.
3) Map ack/nack semantics: on handler success → ack; on error → do not ack (allow redelivery). Respect a max delivery count.
4) Configure subscription options (durable name, prefetch/flow-control) and expose via env vars.

Acceptance Criteria
- Publish/subscribe works against local NATS; durable subscription resumes after restart; messages are redelivered if not acked.

Validate
- Local NATS via docker-compose; publish a message, stop consumer, restart, and assert durable resume and redelivery behavior.
