Task: BE-01.6 — Idempotency guard at ingress (atomic + metrics)

Context
- Prevent duplicate processing using an idempotency key with TTL. Ensure race-safety at ingress and emit metrics for visibility.

Files
- packages/ports/src/idempotency.ts (interface)
- apps/orchestrator/src/index.ts
- apps/orchestrator/test/idempotency.test.ts (new)

Steps
1) Accept header `x-idempotency-key` else derive from deterministic payload hash + actor (avoid PHI in key). Echo key in logs and responses.
2) Use atomic put-if-absent semantics to avoid races. If the current port lacks atomicity, extend interface with `reserve(key, ttlSeconds): Promise<'reserved'|'exists'>` or implement a single-flight lock pattern in-process as a stopgap.
3) On existing key → return 409 `conflict` envelope without side effects. On new reservation → proceed and keep reservation until completion.
4) Emit metrics counters: `idempotency.hit`, `idempotency.miss`, and histogram for `ttlSeconds` used; include `correlationId` in structured logs.
5) Make TTL configurable (default 10 minutes) via `@onecare/config`; document behavior.
6) Add unit tests for sequential and concurrent duplicate requests under `apps/orchestrator/test/idempotency.test.ts`.
7) Hashing: use a stable hash (e.g., SHA-256) of a canonical subset (practiceId, patient.id, narrative length, attachments count) + actor; never include full narrative to avoid PHI in keys.
8) TTL defaults: 600s; configurable via `IDEMPOTENCY_TTL_SECONDS`. Ensure clock-skew tolerance by relying on store TTL expiry.

Acceptance Criteria
- Second identical request within TTL returns 409 without any side effects.
- No concurrent duplicate flows can pass between `exists` and `put` (race-safe semantics proven by test or design).
- Metrics/logs present and tagged with `correlationId`.

Validate
- Two consecutive POSTs with same key; second returns 409.
- Fire 5 concurrent identical requests; exactly 1 proceeds, 4 receive 409.
