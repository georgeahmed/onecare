Task: BE-06.2 — OOH deferral queue (persisted with TTL; flush-on-core-hours)

Context
- Accept submissions out-of-hours per policy, but defer processing until core hours. Records must be persisted with TTL, contain no PHI, and be flushable idempotently at core-hours start.

Files
- apps/access-gate/src/application/portal.state.ts
- packages/ports/src/deferrals.ts (new interface)

Steps
1) Define `DeferralRecord` with stable IDs only (practiceId, submissionId, createdAt, summaryCode); avoid PHI. Add `DeferralStore` interface with `enqueue`, `flushReady(practiceId, untilTs)`, and TTL config.
2) In OOH path and when `policy.accept_submissions` is true, enqueue `DeferralRecord` with TTL to next core-hours window.
3) Implement `flushDeferrals` on core-hours start: publish the appropriate event(s) (e.g., `triage.input` or `portal.notify`) with idempotency keys; ensure dedupe if re-run.
4) Emit metrics: `deferral.enqueue`, `deferral.flush.count`, `deferral.expired`; structured logs include `practiceId` and `correlationId`.
5) Add unit tests for enqueue/flush behaviors and TTL expiry, using in-memory store.

Acceptance Criteria
- OOH submissions are enqueued without PHI; core-hours start flushes items idempotently.
- TTL prevents indefinite growth; metrics/logs show counts and are safe.
- Tests pass without network; typecheck passes.

Validate
- npm run test
