Task: BE-01.4H — Audit WORM semantics + redaction policy

Context
- Ensure immutable, compliant audit logs with minimal data, strict redaction, and resiliency without impacting request latency.

Files
- schemas/audit/audit-event.json (existing)
- packages/ports/src/audit.ts
- apps/orchestrator/src/index.ts
- apps/orchestrator/test/audit.test.ts (new)

Steps
1) Define minimal `AuditEvent` fields (type, ts, correlationId, actorRef, subjectRef, outcome, reasonCode, details?) and enforce redaction on details.
2) Implement async, non-blocking audit writes via a small in-memory queue with bounded size and backoff; drop oldest with a counter when saturated.
3) Add timeouts on audit writes and guard with `callWithGuard` defaults. Never block HTTP responses awaiting audit.
4) Emit metrics: `audit.write.ok`, `audit.write.fail`, and `audit.queue.depth`; log outcome with correlationId.

Acceptance Criteria
- Audit writes do not block request path; bounded queue prevents memory growth.
- Redaction verified in tests; PHI/PII never present in persisted audit docs.

Validate
- Simulate sink failures; observe retries, bounded queue behavior, and failure metrics while HTTP responses remain fast.
