Task: BE-01.11 — Observability: correlationId propagation, metrics, and spans

Context
- Ensure end-to-end observability across HTTP ingress, orchestrator states, outbound calls, and bus publishes. Use structured logs, metrics, and OpenTelemetry spans.

Files
- apps/orchestrator/src/index.ts
- apps/orchestrator/src/application/orchestrator.state.ts
- apps/orchestrator/src/adapters/services/safetyGate.ts
- packages/observability/src/logger.ts (reference)
- src/otel.ts (reference)

Steps
1) Create/propagate `correlationId` from ingress → state context → adapters. Include it in all logs and metrics tags.
2) Wrap critical sections with OTel spans: `ingress`, `normalize`, `safety_gate`, `publish.triage`, `audit`. Add attributes: `correlationId`, `result`, `duration_ms`. Use W3C Trace Context and propagate `traceparent`.
3) Emit metrics: counters `request.total`, `request.success`, `request.deny`, `request.error`; histograms `ingress.latency_ms`, `safety_gate.latency_ms`, `orchestrator.duration_ms`.
4) Ensure logs are structured JSON and redact PHI/PII by default; include only stable IDs. No narrative bodies in logs. Add a `redact(obj)` helper that strips tokens and known PII fields.
5) Add span events for retries and circuit-breaker transitions with attributes `{attempt, delay_ms, state}`.

Acceptance Criteria
- Logs/metrics/spans consistently include `correlationId` and no PHI/PII.
- Spans exist for the main path and visualize in tracer if enabled.
- Unit tests assert logger is called with `correlationId` and safe fields.

Validate
- Run locally with OTEL exporter stub; inspect console spans/logs. Use curl to generate traffic and confirm metrics counters.
