Task: BE-01.8 — Outbound guardrails (timeout/retry/jitter/circuit breaker)

Context
- Wrap external calls (safety gate, audit) with robust guardrails, propagate `correlationId`, and expose metrics/traces.

Files
- apps/orchestrator/src/index.ts
- apps/orchestrator/src/adapters/services/safetyGate.ts
- apps/orchestrator/src/adapters/services/callWithGuard.ts (new)
- apps/orchestrator/src/adapters/services/callWithGuard.test.ts (new)

Steps
1) Implement `callWithGuard(name, fn, { timeoutMs, maxRetries, baseDelayMs })` with AbortController timeout, exponential backoff + jitter, and error classification. Expose a small interface to inject time for tests. Backoff: `delay = baseDelayMs * 2^(attempt-1) + rand(0..baseDelayMs)`.
2) Add a small in-memory circuit breaker per `name` (closed → open on successive failures; half-open after TTL to probe). Log state transitions with `correlationId`.
3) Use `config.safety_gate.timeout_ms` for safety; set conservative defaults for audit writes. Always propagate `x-correlation-id` and `traceparent` on outbound requests.
4) On open circuit for safety gate: apply documented fallback (`rules`) and return a SAFE decision when rules permit; ensure behavior matches Algorithm.md time budget guidance.
5) Emit metrics (`call.retry`, `call.timeout`, `cb.open`) and wrap calls in OTel spans if available. Add unit tests under `callWithGuard.test.ts` to cover retries and CB transitions deterministically. Default params: `timeoutMs=2000`, `maxRetries=2`, `baseDelayMs=100`, `cb.failureThreshold=5`, `cb.cooldownMs=15000`.

Acceptance Criteria
- Timeouts/retries applied with jitter; circuit opens after configured failures and recovers via half-open probe.
- Correlation ID propagated to outbound calls; logs/metrics include correlationId.
- On safety gate unavailability, rules fallback path exercised per config.

Validate
- Simulate failing call; observe retries, backoff, and circuit logs.
- Confirm fallback path returns valid decision and audit event when CB open.
