Task: BE-01.1H — Zero‑trust gate hardening (redaction, rate limit, correlation)

Context
- Strengthen ingress security beyond stubs: pre-auth rate limiting, strict header handling, correlation propagation, and token redaction in all logs.

Files
- apps/orchestrator/src/index.ts
- packages/observability/src/logger.ts
- docs/ERRORS.md (update examples)

Steps
1) Pre-auth limiter: Add a lightweight token-bucket per-IP limiter applied before any parsing; violations return 429 `too_many_requests` with error envelope and `retry-after` header.
2) Correlation: Require/echo `x-correlation-id` for all responses; generate safe ID if missing. Include in every log line.
3) Redaction: Introduce a redaction utility that scrubs Authorization headers, cookies, and known credential fields from logs and error details. Ensure logger defaults to redacting these keys.
4) Strict headers: Normalize casing; reject requests with invalid control characters in headers; enforce `content-type` presence for JSON bodies.
5) Auth/consent: Ensure deny-by-default for missing/invalid tokens or absent consent; emit `audit.event` with minimal details and correlationId.

Acceptance Criteria
- 429 pre-auth returned when rate-limited; logs/audit emitted without sensitive data.
- All logs include correlationId; Authorization and tokens are redacted everywhere.
- 403 on failed auth/consent with structured envelope; audit record emitted.

Validate
- Flood endpoint from one IP to trigger 429; verify envelopes and retry-after.
- Submit with missing/invalid auth; verify 403 and audit.
