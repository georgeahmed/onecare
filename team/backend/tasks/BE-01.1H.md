Task: BE-01.1H — Zero‑trust gate hardening (redaction, rate limit, correlation)

Context
- Strengthen ingress security beyond stubs: pre-auth rate limiting, strict header handling, correlation propagation, and token redaction in all logs.

Files
- apps/orchestrator/src/index.ts
- packages/observability/src/logger.ts
- docs/ERRORS.md (update examples)

Steps
1) Harden header parsing: reject any request with control characters/invalid bytes in header names/values and enforce `content-type: application/json` before body read.
2) Extend redaction rules to cover error details emitted from the state machine and ensure regression tests for sensitive headers/cookies.
3) Add integration tests that exercise the pre-auth limiter and strict header rejection paths, asserting 429/400 envelopes with correlation IDs.

Acceptance Criteria
- Header validation rejects malicious input with structured 400 responses; sensitive headers always redacted.
- 429 limiter path covered by tests; logs/audits carry correlation IDs without secrets.

Validate
- Flood endpoint from one IP to trigger 429; verify envelopes and retry-after.
- Send requests with invalid headers/control chars; expect 400 with safe envelope.
