Task: BE-01.3H — Reliable publish (ack/retry) and DLQ prep

Context
- Improve message publishing reliability with acks, retry policy, and DLQ preparation without introducing duplicates.

Files
- packages/events/src/topics.ts
- packages/events/src/contracts/dlq-event.ts (generated)
- apps/orchestrator/src/adapters/busUtil.ts (new)
- apps/orchestrator/test/publish.test.ts (new)
- docs/EVENTS.md (update)

Steps
1) Define a publish helper that awaits an ack (or simulates one with MemoryBus) with timeout. On timeout or error, retry with exponential backoff up to config max.
2) Ensure idempotency headers/keys are included with publish to avoid duplicates on retries; capture correlationId.
3) After max retries, publish a minimal DLQ event (`DlqEvent`) to `Topics.broker.deadLetter` with failure metadata; ensure it validates against schema.
4) Emit metrics: `publish.ok`, `publish.retry`, `publish.fail`, and per-topic histograms for publish time.

Acceptance Criteria
- Normal publish returns promptly with ack; timeouts trigger bounded retries; after max attempts, DLQ publish occurs.
- No duplicate application-side side-effects due to retries; idempotency respected.

Validate
- Simulate transient failure then recovery; verify retry then success.
- Simulate persistent failure; verify DLQ event contents and schema compliance.
