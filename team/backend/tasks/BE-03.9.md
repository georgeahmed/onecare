Task: BE-03.9 — Fallbacks for missing ML (rules-based scoring)

Context
- When ML services (acuity/similarity) are unavailable or circuit-open, apply a transparent, configurable rules-based fallback to produce safe triage outcomes.

Files
- apps/triage/src/application/scoring.ts (extend)
- packages/config/src/index.ts (read defaults)
- docs/Algorithm.md (reference: red_flag_set, priority thresholds)

Steps
1) Detect ML unavailability via dependency status or CB state; short-circuit to fallback path within a strict time budget.
2) Implement rules: keyword red flags → `STAT`/`URGENT`; default weights on available features → numeric score → priority thresholds mapping.
3) Record `reasons[]` explaining decision (e.g., `"rule:red_flag:chest_pain"`). Avoid PHI; store compact codes.
4) Ensure consistent outcomes with ML path when available (e.g., tolerance within configured delta); add tests for both paths.

Acceptance Criteria
- Fallback produces safe, explainable outcomes; consistent with configured thresholds.
- Time budget enforced; no blocking on ML when unavailable.

Validate
- Unit tests simulating CB-open/timeouts; assert decision and reasons.
