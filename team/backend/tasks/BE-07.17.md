Task: BE-07.17 — Health/readiness + graceful shutdown (ICS)

Context
- Expose liveness/readiness probes for ICS Hub that reflect bus connectivity and repository/port health without generating load. Implement graceful shutdown that drains in-flight routing/ack work.

Files
- apps/ics-hub/src/index.ts (HTTP probe routes)
- apps/ics-hub/src/application/ics.state.ts (drain coordination if needed)
- packages/bus/src/* (health signal)
- packages/ports/src/fhir.ts (optional repo health)

Steps
1) Add `/healthz` (always 200) and `/readyz` (200 only when bus is connected, durable subscriptions are active, and critical ports are healthy). Keep responses minimal; no envelopes.
2) Cache readiness for 1–5s to avoid probe amplification. Update cached status on connection events.
3) On SIGTERM/SIGINT: stop consuming, wait for in-flight processing to complete with a fixed grace period, close bus/ports, then exit. Expose `inflight.messages` gauge and log shutdown events.
4) Emit metrics: `ics.ready.ok/fail`, `ics.shutdown.start/timeout`. Ensure logs include no PHI and add correlation-free fields only.
5) Document probe config (initialDelay, period, timeout) and shutdown expectations in README.

Acceptance Criteria
- `/healthz` stable; `/readyz` flips 200↔503 based on bus/ports; probes cached; shutdown drains in-flight work within timeout.

Validate
- Start service; kill broker → `/readyz` returns 503; restore → 200. Send SIGTERM under load and verify graceful drain in logs/metrics.
