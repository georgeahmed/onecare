Task: BE-04.6 — DLQ and retry policy for booking

Context
- Make booking message handling resilient with bounded retries and a Dead Letter Queue (DLQ). Include metadata to aid reprocessing.

Files
- packages/events/src/topics.ts (booking.* and booking.*.dlq)
- apps/booking/src/index.ts (producer/consumer policies)
- docs/EVENTS.md (document DLQ envelope)

Steps
1) Define DLQ topics for booking streams (e.g., `booking.appointmentCreated.dlq`).
2) Retry policy: exponential backoff with jitter, max 3 attempts for retryable errors.
3) On non-retryable or max attempts exceeded: publish to DLQ with `originalTopic`, `attempts`, `correlationId`, `errorCode`, `reason`.
4) Ensure idempotency keys present in messages and enforced on consume.

Acceptance Criteria
- DLQ topics defined; retry bounded; DLQ payloads include required metadata.
- Idempotency enforced on redelivery; no duplicate side-effects.

Validate
- Simulate retries then DLQ; simulate immediate DLQ for non-retryable.
