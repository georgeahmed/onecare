Task: BE-01.7 — Normalize→FHIR pipeline + profile validation hook

Context
- Prepare normalization and validation before FHIR upsert. Keep mapping logic pure and testable; delegate heavy validation to a port.

Files
- apps/orchestrator/src/application/normalize.ts (new)
- apps/orchestrator/src/application/normalize.test.ts (new)
- apps/orchestrator/src/index.ts (import/use)
- packages/ports/src/fhir.ts (reuse repo port)
- schemas/ingest/portal-submission.json (contract validation)
 - packages/events/src/contracts/ingest.ts (generated types reference)

Steps
1) Add `normalizeToFhir(submission: PortalSubmission): Bundle` as a pure function that creates a FHIR `Bundle` (transaction) stub with minimal `Patient`/`Communication`/`DocumentReference` refs as applicable. No I/O inside. Ensure deterministic ordering of entries.
2) Validate the inbound `PortalSubmission` against the generated TS types; if needed, add a lightweight JSON Schema validator in the orchestrator path to return `invalid_input` on schema mismatch.
3) Add `validateProfiles(bundle): Promise<void>` hook that will later call an external validator adapter; for now, stub and allow opt-in failure with code `invalid_fhir`.
4) Wire normalization + validation before calling `FhirRepository.upsertBundle`; ensure errors return proper envelopes and emit audit events with `correlationId`. Include optional `mpiLink(patient)` stub to attach existing patient reference.
5) Add unit tests for `normalizeToFhir` (pure mapping) using small fixtures under `apps/orchestrator/src/application/normalize.test.ts`. Include edge cases: missing optional fields, minimal valid payload, multi-attachment submissions. Snapshot top-level Bundle fields and entry resource types only (no PHI).

Acceptance Criteria
- Invalid input returns 400 with `invalid_input`; invalid profile hook returns `invalid_fhir`.
- `normalizeToFhir` is side-effect free and easily testable.
- Typecheck passes; mapping yields a bundle stub with expected entries.

Validate
- Simulate thrown error in `validateProfiles`; observe envelope response and audit entry.
