Task: BE-02.6 — Delivery semantics & idempotency

Context
- Provide at-least-once delivery with idempotent publish/consume semantics to avoid duplicate side effects across services.

Files
- packages/bus/src/types.ts (metadata)
- packages/bus/src/natsBus.ts
- packages/ports/src/idempotency.ts (store integration)

Steps
1) Add optional `idempotencyKey` field to publish API metadata; include in headers or envelope attributes when supported.
2) On consume, require handlers to accept metadata (correlationId, attempt, idempotencyKey). Document usage with IdempotencyStore and provide an example helper.
3) Add sample dedupe wrapper (reserve→handle→commit) for consumers; ensure it composes with retries and DLQ.

Acceptance Criteria
- Publish can carry idempotency keys; consume path demonstrates dedupe integration.

Validate
- Unit tests for duplicate deliveries: exactly one side-effect execution with the dedupe wrapper.
