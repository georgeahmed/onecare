Task: BE-01.12 — Security hardening (SSRF, sanitation, consent)

Context
- Reduce attack surface and enforce deny-by-default. Prevent SSRF, sanitize inputs/headers, and ensure consent checks are authoritative.

Files
- apps/orchestrator/src/index.ts
- packages/security/src/index.ts
- docs/SECURITY.md (add notes)

Steps
1) Implement URL allowlist for outbound endpoints (exact URL or hostname list). Reject IP literals and private/link-local ranges (IPv4 10/172.16/192.168, 127.0.0.0/8; IPv6 ::1, fc00::/7, fe80::/10).
2) Resolve DNS and verify the resolved IP is public before connecting. Disable redirects to non-allowlisted hosts and ignore proxy env for these calls.
3) Sanitize/normalize inbound/outbound headers (strip hop-by-hop headers; normalize `x-correlation-id`; no `authorization` echo). Redact secrets in logs.
4) Ensure consent enforcement is deny-by-default; missing consent → 403 with audit event and correlationId. Log safe reason codes only.
5) Validate and sanitize filenames/URIs if present; reject invalid formats (use JSON Schema `format` and allowlist schemes).

Acceptance Criteria
- Outbound calls only target allowlisted hosts; violations denied and audited.
- Inputs sanitized; logs contain no raw secrets.
- Consent denials return 403 with structured envelope and audit.

Validate
- Attempt outbound to non-allowlisted host; receive blocked outcome + audit record.
- npm run typecheck && npm run test
