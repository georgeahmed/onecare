Task: BE-06.4 — Portal notify event (contract-first, idempotent, DLQ)

Context
- Publish `portal.notify` when portal state changes (up/down/OOH), using a contract-first approach, idempotency keys, and DLQ for poison messages.

Files
- schemas/portal/notify.json (new)
- packages/events/src/topics.ts (Topics.portal.notify exists)
- apps/access-gate/src/application/portal.state.ts
- docs/EVENTS.md (reference)

Steps
1) Define `schemas/portal/notify.json` with explicit fields (practiceId, state, reasonCode, at). Set `additionalProperties: false`; add `$id` and `format` where relevant.
2) Run codegen (TS, optional Py) and import the generated type. Validate event payloads before publish.
3) Compute idempotency key from (practiceId + state + at truncated to minute). Avoid PHI in payload.
4) Publish envelope with `correlationId` and retry policy; on non-retryable failures or retries exceeded, route to DLQ (see BE-06.9).
5) Add unit tests to assert shape validation, idempotency key stability, and publish-on-change only.

Acceptance Criteria
- Event conforms to schema; duplicates suppressed by idempotency key across rapid toggles.
- DLQ policy defined; tests pass; no PHI.
