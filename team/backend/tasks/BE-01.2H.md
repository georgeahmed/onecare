Task: BE-01.2H — Orchestrator config schema + startup validation

Context
- Enforce contract-first configuration using JSON Schema with validation at startup; fail fast on invalid config and log the effective, redacted config once.

Files
- schemas/config/orchestrator.json (existing)
- packages/config/src/contracts/orchestrator.ts (generated)
- apps/orchestrator/src/index.ts
- apps/orchestrator/test/config.test.ts (new)

Steps
1) Validate loaded config against `OrchestratorConfig` JSON Schema at startup; exit with error on invalid config.
2) Freeze the effective config object to prevent runtime mutation; log it once with redaction of sensitive fields.
3) Support SIGHUP-based reload for non-secret fields; on reload, re-validate and swap atomically; log version/hash.
4) Provide typed accessors for common settings (timeouts, retries, limits) to avoid magic numbers in code.

Acceptance Criteria
- Invalid config causes startup failure with clear log; valid config logged once without sensitive fields.
- Optional reload succeeds with validation; runtime uses updated values safely.

Validate
- Provide an invalid config env; observe startup failure.
- Trigger reload; verify updated limits applied.
