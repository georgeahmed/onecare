Task: BE-01.5 — Centralized error handling and envelope mapping

Context
- Provide a consistent, safe error envelope for HTTP and event flows per `docs/ERRORS.md`. Classify errors, map to HTTP status codes, and propagate `correlationId` without leaking internals.

Files
- apps/orchestrator/src/index.ts
- apps/orchestrator/src/application/error.ts (new)
- apps/orchestrator/test/error.test.ts (new)
- docs/ERRORS.md (reference)

Envelope Shape (HTTP)
{
  "error": {
    "code": "invalid_input|forbidden|...",
    "message": "short, safe",
    "details": {"field": "reason"},
    "correlationId": "..."
  }
}

Steps
1) Add `errorEnvelope(code, message, details?, correlationId?)` returning the documented shape; export typed `ErrorCode` union (e.g., `unauthorized`, `forbidden`, `invalid_input`, `payload_too_large`, `unsupported_media_type`, `conflict`, `upstream_timeout`, `upstream_unavailable`, `too_many_requests`, `internal_error`, `invalid_fhir`). Ensure the union is generated from `schemas/common/error-envelope.json` and re-exported.
2) Add `mapErrorToStatus(code)` ensuring correct 4xx/5xx mapping; map `unauthorized→401`, `forbidden→403`, `invalid_input→400`, `too_many_requests→429`, `payload_too_large→413`, `unsupported_media_type→415`, `upstream_timeout→504`, `upstream_unavailable→503`, else `500`. Never include stack traces in responses.
3) Wrap `/safety-check` handler with a small `handleHttp` helper that catches exceptions, logs once (with redaction), and returns the envelope with `x-correlation-id` echoed.
4) Ensure error logging includes `correlationId`, `code`, and a safe `reason`, with sensitive fields redacted.
5) Add unit tests for mapping (code → status), and a sample error response snapshot (shape only, no internals) under `apps/orchestrator/test/error.test.ts`.
8) Event flows: do not publish error envelopes on the bus. Instead, produce an audit event and/or route to DLQ per BE-01.16 with metadata: `correlationId`, `errorCode`, `reason`.
6) Emit metrics: counters per code (e.g., `error.http.forbidden`), and a duration histogram for request handling; tags include `code` and `route`.
7) Document the mapping in `docs/ERRORS.md` and add curl examples for common cases (401/403/413/415/429/5xx).

Acceptance Criteria
- Invalid/missing auth returns 403 with envelope `{ error: { code: 'forbidden', correlationId } }`.
- Invalid payload returns 400 with `invalid_input`; upstream timeout returns 504 mapped from `upstream_timeout`.
- Typecheck passes; logs redact sensitive data; no stack traces in HTTP bodies.
