Task: BE-01.10 — HTTP ingress validation + body size limits

Context
- Harden HTTP ingress to protect against malformed inputs and abuse. Enforce JSON Schema validation, strict content types, and bounded payload sizes. Echo `x-correlation-id` and return structured error envelopes.

Files
- apps/orchestrator/src/index.ts
- apps/orchestrator/src/application/error.ts (reuse from BE-01.5)
- schemas/ingest/portal-submission.json (contract)

Steps
1) Enforce `content-type: application/json` and reject others with `unsupported_media_type` (415). Be tolerant of `; charset=utf-8`.
2) Add streaming body parser with a strict byte limit (default 256KB, configurable via `@onecare/config`). If `Content-Length` > limit, reject early. On read overflow → 413 `payload_too_large` envelope.
3) Validate payload against generated TS types and JSON Schema (Ajv). On failure → 400 `invalid_input` envelope with safe `details` (array of `{path, message}`), capped at 5 errors.
4) Always set and echo `x-correlation-id`; ensure error handler (BE-01.5) maps errors consistently and never leaks internals. Sanitize and normalize headers; strip hop-by-hop headers.
5) Add unit tests for: wrong content-type, oversized body, invalid schema, invalid JSON (malformed), and max-error-details cap.

Acceptance Criteria
- Requests > limit rejected with 413 and standard envelope.
- Invalid JSON or schema mismatch yields 400 `invalid_input` with stable shape.
- Typecheck passes; handler remains side-effect-free on invalid input.

Validate
- curl tests for content-type, size, and invalid fields; assert codes and envelope shape.
