Task: BE-03.7 — Event-driven ingress (triage.input consumer)

Context
- Consume `triage.input` from the event bus, enforce idempotency, and drive the triage pipeline (scoring → dedup → task creation → notify) with at-least-once semantics.

Files
- packages/events/src/topics.ts (triage.input)
- packages/bus/* (adapter)
- apps/triage/src/index.ts (consumer wiring)
- apps/triage/src/application/* (scoring/dedup/assignment)
- packages/ports/src/idempotency.ts (store)

Steps
1) Create a consumer for `Topics.triage.input` with durable subscription. Parse `EventEnvelope<TriageInput>`; propagate `correlationId`.
2) Enforce idempotency: derive or read an idempotency key; reserve via `IdempotencyStore` before processing; on conflict → ack and no-op.
3) Process with bounded retries/backoff (2 retries, jitter). On non-retryable errors, publish to DLQ with compact error report (no PHI).
4) Publish outcomes (`tasks.created`, `tasks.updated`) with idempotency keys and `correlationId`.
5) Emit metrics: `consume.ok`, `consume.error`, `consume.retry`, `consume.dlq` tagged by topic and error code.

Acceptance Criteria
- Idempotent consumption with durable subs; retries bounded; DLQ on poison.
- CorrelationId flows through logs and published envelopes.
- Metrics counters visible for success/error/retry/dlq.

Validate
- Unit tests stubbing bus callbacks to simulate success/retry/DLQ paths (no network).
