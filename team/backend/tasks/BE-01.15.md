Task: BE-01.15 — Contract compliance & codegen (schemas → types → validators → CI gate)

Context
- Enforce API/Contract-first workflow. Update JSON Schemas under `schemas/` first, then regenerate TypeScript and Python models, wire validators at ingress, and add CI gates to block drift. Maintain `$id` semantic versioning and backward-compat rules.

Files
- schemas/common/*.json, schemas/ingest/portal-submission.json
- packages/events/src/*.ts (generated or hand-maintained types)
- scripts/codegen/* (TS/Python model generation)
- apps/orchestrator/src/index.ts (wire validator)
- docs/SCHEMAS.md, docs/USAGE.md (reference)
 - .github/workflows/ci.yml (schema/codegen gate)

Steps
1) Schema hygiene: ensure `$id`, `title`, `description`, `default`, and `additionalProperties: false` are present; add `format` where applicable (`date-time`, `uri`).
2) Versioning: if breaking change, bump `$id` version and document migration notes; maintain dual-read/publish if feasible.
3) Codegen: run TS/Python generators to refresh models; ensure no `any` leaks. Publish generated types in `@onecare/events` where appropriate.
4) Validators: compile JSON Schema validators (e.g., Ajv) at boot; validate `PortalSubmission` at HTTP ingress and return `invalid_input` envelope on mismatch.
5) CI Gate: add `npm run typecheck && npm run test` and a schema drift check (hash or git diff on generated files) to fail PRs when codegen not run. Include `npm run codegen` step and fail if `git diff --exit-code` shows changes.
6) Docs: update `docs/SCHEMAS.md` on changes; add examples to service README and `docs/USAGE.md` if commands/scripts change.

Acceptance Criteria
- Schemas compile; generated TS models are up-to-date and used at ingress.
- CI fails on stale generated files or typecheck/test failures.
- Breaking changes have bumped `$id` and documented migration notes.

Validate
- Intentionally mutate a schema, run codegen, observe model updates; run `npm run typecheck && npm run test`.
