Task: BE-07.2 — Workflow Automation triggers (policy-driven)

Context
- Listen to `tasks.updated` and other trigger topics; evaluate deterministic policy rules for recalls/repeats/docs and emit `tasks.created` with provenance. Keep business logic pure and testable.

Files
- apps/ics-hub/src/application/automation.rules.ts (new)
- apps/ics-hub/src/application/ics.state.ts (integration)
- packages/events/src/contracts (tasks schemas)

Steps
1) Define a small, pure rules engine: `evaluateAutomationTriggers(event, config) -> Intent[]` where `Intent` includes type, minimal payload, and reason.
2) Load trigger config from env/JSON (e.g., repeat intervals, doc patterns) and pass into evaluator; forbid network I/O in rule evaluation.
3) For each Intent, create a `tasks.created` payload with provenance and correlationId; side effects (publish/audit) handled in a separate adapter layer.
4) Add unit tests with deterministic fixtures to ensure the same inputs yield the same Intents.

Acceptance Criteria
- Given specific `tasks.updated` events and config, expected Intents are produced; no duplicates for unchanged state.
- Typecheck passes; unit tests run fast and without network.

Validate
- npm run test
