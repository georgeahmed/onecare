Task: BE-06.8 — Front-door rate limiting (tenant/account) for access portal

Context
- Protect portal entry from bursts and abuse using a token-bucket limiter keyed by tenant/account. Return structured 429 envelopes and emit metrics.

Files
- apps/access-gate/src/index.ts (ingress middleware)
- @onecare/config (defaults)

Steps
1) Implement token-bucket limiter with configurable capacity/refill by tenant/account. Store buckets in an LRU cache with TTL.
2) On limit exceeded, return 429 envelope `{ error: { code: 'rate_limited', correlationId } }` and `Retry-After` header with seconds.
3) Emit metrics: `rate.limit.hit`, `rate.limit.block` tagged by tenant/account. Log safe structured entries including `correlationId`.
4) Unit tests: simulate N requests hitting the limit; assert 429s and headers; no network I/O.

Acceptance Criteria
- Correct 429 behavior with standard envelope and `Retry-After`.
- Metrics/logs reflect limits; tests deterministic.

Validate
- Run tests; manual curl with low limits in dev to observe behavior.
