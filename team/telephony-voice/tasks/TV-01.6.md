Task: TV-01.6 — ASR client guardrails (timeout/retry/jitter/CB; SSRF allowlist; TLS)

Context
- Harden outbound calls to the ASR service: apply timeouts, retries with jitter, circuit breaker, and SSRF/TLS protections. Propagate `correlationId` and keep logs PHI-safe.

Files
- apps/telephony/src/adapters/asr.client.ts
- packages/observability/src/logger.ts, src/otel.ts
- docs/ERRORS.md (error mapping)

Steps
1) Implement `callWithGuard` around ASR calls: AbortController timeout (config default 5s), max 2 retries with exponential backoff + jitter; classify retryable vs non-retryable errors.
2) Per-destination circuit breaker: open after N failures; half-open probe after TTL; log state transitions with safe fields (no transcript contents).
3) Enforce SSRF: ASR host allowlist, block private/link-local/loopback; disable redirects; require TLS (https) in non-dev.
4) Always set minimal headers; propagate `x-correlation-id` and `traceparent` only.
5) Emit metrics (`asr.retry`, `asr.timeout`, `asr.cb.open`) and wrap calls in spans (`asr.call`).

Acceptance Criteria
- Guardrails active; CB opens/recover; SSRF prevention; correlationId propagated; PHI-safe logs.

Validate
- Fault injection tests simulate timeouts/failures; verify retries/CB and blocked SSRF attempts.
