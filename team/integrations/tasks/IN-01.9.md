Task: IN-01.9 — Circuit breaker + backoff policy (idempotent-safe retries)

Context
- Improve resilience by wrapping FHIR/Object Store calls with a circuit breaker and exponential backoff with jitter. Only retry idempotent operations.

Files
- packages/ports/src/fhir.ts
- packages/ports/src/object-store.ts
- packages/observability/src/otel.ts, logger.ts

Steps
1) Implement `callWithGuard(name, fn, { timeoutMs, maxRetries, baseDelayMs })` using AbortController for timeout and exponential backoff + jitter for retries.
2) Add a lightweight per-destination circuit breaker (closed → open after N consecutive failures; half-open after TTL); log transitions with safe fields and correlation-free context.
3) Classify operations: allow retries for GET/HEAD/PUT to Object Store and FHIR $transaction only if idempotency keys are present; no retries for create without keys.
4) Emit metrics: `call.retry`, `call.timeout`, `cb.open`, and wrap calls in OTEL spans where available.

Acceptance Criteria
- Guardrails applied; CB opens/recover; retries restricted to idempotent ops.

Validate
- Fault injection tests simulate failures/timeouts and confirm retries/circuit behavior.
