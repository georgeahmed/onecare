Task: IN-01.8 — SSRF guardrails & TLS enforcement (FHIR/Object Store)

Context
- Protect outbound HTTP calls to FHIR and Object Store against SSRF and insecure transport. Enforce host allowlists, deny private/loopback ranges, and require TLS in non-dev.

Files
- apps/* (consumers) via FHIR client and Object Store adapters
- packages/ports/src/fhir.ts (client usage)
- packages/ports/src/object-store.ts
- docs/ERRORS.md (mapping)

Steps
1) Add URL allowlist config for FHIR and Object Store endpoints. Reject IP literals and block private/link-local/loopback subnets.
2) Resolve DNS and verify resolved IP is public before connecting. Disable automatic redirect following or validate redirect target against allowlist.
3) Require TLS (https) in non-dev; enable certificate validation; document how to configure CA bundle where needed.
4) Sanitize outbound headers to a minimal set; always propagate `x-correlation-id` and `traceparent` only.
5) Unit tests: disallow private IPs/loopback; allow listed hostname; validate headers are minimal.

Acceptance Criteria
- FHIR/Object Store calls are SSRF-hardened and TLS-enforced; tests cover allow/deny behavior.

Validate
- Run unit tests; attempt to set a loopback endpoint in dev and confirm rejection with clear error mapping.
