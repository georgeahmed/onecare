Task: IN-02.1b — Resilience: timeout/retry/jitter, connection pooling, circuit breaker

Context
- Ensure the client exhibits consistent behavior under transient failures and avoids thundering herds.

Files
- packages/ports/src/gp-connect.ts
- apps/booking (later consumer)

Steps
1) Add per-call options `{ timeoutMs, maxRetries, baseDelayMs }`; default to 2s/2 retries with jitter.
2) Use a single HTTPS agent with keep-alive; configure max sockets to avoid saturation.
3) Add a simple circuit breaker keyed by operation/endpoint (closed → open after N failures; half-open after TTL) with logs/metrics.

Acceptance Criteria
- Timeouts enforced; retries bounded; circuit breaker transitions logged; no resource leaks.

Validate
- Unit tests using http mocks simulating timeouts/errors/flapping; assert retry count and CB behavior deterministically.
