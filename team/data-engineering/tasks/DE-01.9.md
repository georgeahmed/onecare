Task: DE-01.9 — Storage design (Parquet layout, partitioning, schema evolution, compaction)

Context
- Choose an efficient storage layout for analytics metrics to support rollups and queries at scale, with predictable costs.

Files
- docs/adr/2025-..-analytics-storage.md (new)
- scripts/etl/storage_layout.ts or .py (new)

Steps
1) Select Parquet (columnar) with partitioning by `date=YYYY-MM-DD` and optionally `practiceId` when present in labels; document rationale in ADR.
2) Define a stable schema mapping (name, value, labels JSON, ts) and schema evolution strategy (additive fields only; backfill policy).
3) Implement compaction: merge small files into target sizes (e.g., 128–256MB) periodically; track job metadata.
4) Provide a simple reader/writer abstraction for Parquet; unit tests write/read roundtrip and partition pruning.

Acceptance Criteria
- ADR recorded; Parquet layout + partitioning documented; compaction job spec written; tests for read/write.

Validate
- Run a small synthetic write/read and compaction in dev.
