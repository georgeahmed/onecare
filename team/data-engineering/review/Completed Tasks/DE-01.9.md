Task: DE-01.9 — Storage design (Parquet layout, partitioning, schema evolution, compaction)

Context
- Choose an efficient storage layout for analytics metrics to support rollups and queries at scale, with predictable costs.

Current State
- `docs/adr/2025-10-18-analytics-storage.md` captures the Parquet-first storage decision, partition keys (`date/metric/window/label`), schema evolution policy, and compaction targets (192–256 MiB).
- `scripts/analytics_storage_layout.js` provides partition planning, Parquet writer/reader helpers with CLI (`write`, `compact`, `inspect`), and compaction manifest support.
- `test/scripts/analytics_storage_layout.test.ts` exercises partition pruning, roundtrip integrity, and compaction manifest emission against synthetic rollups.

Files
- docs/adr/2025-10-18-analytics-storage.md (new)
- scripts/analytics_storage_layout.js (new)

Steps
1) Record storage decisions in the ADR (Parquet/Delta vs alternatives, partition columns, cost considerations, schema evolution).
2) Implement a layout planner that writes rollup batches to partitioned Parquet (e.g., `date=YYYY-MM-DD/metric=<name>/`) and enforces additive-only schema changes.
3) Build a compaction routine that merges small files into target sizes (128–256MB) and tracks run metadata for observability.
4) Provide a reader/writer helper with tests covering partition pruning and roundtrip accuracy on synthetic data.

Acceptance Criteria
- ADR approved; planner writes to partitioned Parquet with documented schema evolution; compaction job and helpers covered by tests.

Validate
- Run planner+compaction over sample data and inspect partitions and metadata outputs.
