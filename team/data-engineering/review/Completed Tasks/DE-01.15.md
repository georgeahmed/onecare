Task: DE-01.15 — Pipeline observability (ingest lag, sink latency, error rates; dashboards)

Context
- Make data pipelines observable with metrics for ingestion lag, sink write latency, error/retry/DLQ counts, and job durations. Provide dashboard definitions.

Current State
- `apps/analytics/src/consumer.ts` exports ingest/dlq counters, lag histograms, and privacy-safe logs that power the dashboard panels.
- Offline jobs now emit structured metrics via `@onecare/observability` (`analytics.rollup.*`, `analytics.quality.*`, `analytics.quarantine_export.*`) with run identifiers, and `docs/ANALYTICS_DASHBOARDS.md` captures the corresponding panels/alerts and metric names.

Files
- scripts/metrics_rollup.js (instrument)
- scripts/analytics_quality.js (instrument)
- scripts/analytics_quarantine_export.js (instrument)
- docs/ANALYTICS_DASHBOARDS.md (update)

Steps
1) Instrument the offline/ETL scripts to emit structured metrics (duration, processed rows, success/failure, lag) via `@onecare/observability` counters/histograms and include `correlationId` where available.
2) Expose a lightweight status emitter (e.g., Prometheus scrape endpoint or JSON metrics dump) so CI/cron jobs can collect the new metrics; document environment variables and CLI flags.
3) Update the dashboard guide with panels/alerts for ETL duration, processed rows, and failure rates, aligning metric names with the new instrumentation.

Acceptance Criteria
- Offline jobs surface metrics alongside runtime ingest metrics; dashboards document how to visualise them; logs stay PHI-safe.

Validate
- Run consumer + ETL locally; confirm metrics/structured logs and dashboard queries.
