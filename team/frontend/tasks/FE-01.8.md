Task: FE-01.8 — Accessibility WCAG 2.2 AA (focus, keyboard, ARIA, contrast)

Context
- Ensure the portal is accessible and delightful for all users. Meet WCAG 2.2 AA with strong keyboard navigation, focus management, ARIA semantics, and sufficient color contrast.

Files
- apps/portal/src/* (components/forms/layout)
- docs/CONVENTIONS.md (a11y section)

Steps
1) Keyboard/focus: logical tab order; visible focus rings; skip‑to‑content; restore focus after route changes; trap focus in dialogs.
2) Semantics: landmarks (header/nav/main/footer); labels with `for`/`aria-labelledby`; error associations; live regions for async status.
3) Contrast: adopt tokenized colors ensuring contrast ≥ 4.5:1; add high‑contrast theme toggle.
4) Inputs: large touch targets; device‑appropriate keyboards; clear required indicators; accessible error summaries linked to fields.
5) Testing: integrate axe-core checks and screen reader smoke tests (NVDA/VoiceOver guidance). Add unit tests for focus cycling.

Acceptance Criteria
- Axe passes on core flows; keyboard-only operation works; color contrast verified; screen-reader announcements meaningful.

Validate
- Run e2e a11y scan; manual keyboard + SR checks on form and result screen.
