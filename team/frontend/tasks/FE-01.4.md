Task: FE-01.4 — POST /safety-check with x-correlation-id; display SafetyDecision

Context
- Wire the intake form to orchestrator `/safety-check`. Propagate correlation IDs, handle timeouts, and render either SafetyDecision or an error envelope.

Files
- apps/portal/src/lib/api.ts (implement fetch with AbortController)
- apps/portal/src/components/IntakeForm.tsx (call API and render result)
- apps/portal/src/components/ErrorAlert.tsx (from FE-01.3)

Steps
1) Implement `submitIntake(payload, { signal })` that POSTs to `ORCH_URL/safety-check` with `content-type: application/json` and `x-correlation-id` (UUIDv4).
2) Use `AbortController` with a 2s default timeout; on timeout, surface a friendly error via `ErrorAlert`.
3) On 200, render the returned SafetyDecision summary; on >=400, parse envelope and render `ErrorAlert`.
4) Redact potential sensitive data in any logs; never log payloads.

Acceptance Criteria
- Happy path displays decision; error paths show correct envelope mapping (400/403/429/503) with correlationId.
- Requests carry `x-correlation-id`; timeouts are enforced.

Validate
- Manual: run orchestrator locally and submit a valid/invalid payload; inspect network headers and UI behavior.
