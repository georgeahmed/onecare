Task: FE-02.13 — State/data architecture (idempotent confirm; cancel/retry)

Context
- Keep state simple and robust: avoid duplicate confirms, support cancel/retry paths, and cache search results.

Files
- apps/portal/src/lib/bookingData.ts
- apps/portal/src/hooks/useBookingFlow.tsx
- apps/portal/src/components/booking/ConfirmBooking.tsx
- apps/portal/src/lib/api.ts

Steps
1) Cache search results keyed by filters to avoid refetching on back/forward (`BookingCache`).
2) Centralize confirm action with idempotency key handling and a single inflight lock to prevent duplicates; expose cancel/retry methods (offline queue + confirm booking helper).
3) Provide a typed state context limited to booking flows; document patterns (`useBookingFlow`).

Acceptance Criteria
- Data layer prevents duplicate actions; cached results improve UX; patterns documented.

Validate
- Unit tests for inflight lock/idempotency and caching.
