Task: FE-01.2 — Client-side JSON Schema validation for submission (errors inline)

Context
- Validate the payload against `schemas/ingest/portal-submission.json` to keep client and server rules aligned. Use compiled validators for speed and determinism.

Files
- apps/portal/src/lib/validation.ts (new)
- apps/portal/src/components/IntakeForm.tsx (wire validation)
- schemas/ingest/portal-submission.json (contract; source of truth)

Steps
1) Add an Ajv-based validator that compiles `portal-submission.json` at build time; cache the compiled function.
2) Implement a pure mapper from Ajv errors to field-level messages and a top-level error summary.
3) On submit, validate; if invalid, render inline errors and summary; otherwise call the submit stub (FE-01.1).

Acceptance Criteria
- Invalid inputs surface deterministic messages tied to field paths; valid payloads pass with no errors.
- No network calls occur during validation; messages contain no PHI echoing.

Validate
- Unit tests for the mapper using positive/negative samples; manual form checks for a few invalid cases.
