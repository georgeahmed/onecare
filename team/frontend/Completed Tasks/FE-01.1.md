Task: FE-01.1 — Scaffold portal intake form (practiceId, patient.id, narrative, channel)

Context
- Create an accessible, minimal intake form aligned with `schemas/ingest/portal-submission.json`. Avoid logging PHI/PII and prepare for later API integration.

Files
- apps/portal/src/pages/Intake.tsx (new)
- apps/portal/src/components/IntakeForm.tsx (new)
- apps/portal/src/lib/types.ts (PortalSubmission shape)
- apps/portal/src/lib/api.ts (stub submit; implemented in FE-01.4)

Steps
1) Add a route `/intake` and page layout with a heading and description.
2) Build a controlled form capturing `practiceId`, `patient.id`, `channel` (default `web`), and `narrative`.
3) Type the form data as `PortalSubmission` based on the schema fields; keep camelCase.
4) Implement a submit handler that calls a stub `submitIntake(payload)` and shows a non-PII confirmation state.
5) Ensure basic a11y (labels/ids, fieldset/legend where applicable, keyboard nav) and no console logs of form values.

Acceptance Criteria
- Form renders, required fields indicated, and submit transitions to a confirmation state using the stub.
- Types match schema shape; no PHI/PII is logged; basic accessibility checks pass.

Validate
- Manual: open the `/intake` page in dev and verify fields/flow.
