Task: FE-01.16 — Friendly error states (429/503/504 mapping; copy/backoff UX)

Context
- Reduce frustration with clear, empathetic messages and guided retries for common errors (rate limit, over capacity, gateway timeout).

Files
- apps/portal/src/components/ErrorAlert.tsx
- apps/portal/src/components/RetryNotice.tsx
- apps/portal/src/components/booking/BookingErrorView.tsx

Steps
1) Map backend error codes to friendly titles, short explanations, and actions (retry/backoff, contact practice, try later). Avoid technical jargon.
2) Provide contextual retry with exponential backoff; for 429 include Retry‑After countdown (see booking confirmation retry handling).
3) Keep state on where the user was; allow resuming without losing input (autosave draft + offline queue).

Acceptance Criteria
- Error views feel calm, clear, and actionable; backoff integrated; inputs preserved.
